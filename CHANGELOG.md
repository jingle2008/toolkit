## [Unreleased]

### Added
- **TUI help filter.** `/` in help narrows it as you type, by key or description; a section whose title matches stays whole (`/sort`), and `Esc` clears the filter before it closes help. On a short terminal, a modal nearly as tall as the screen now opens on a blank screen rather than over fragments of the view (`GPUN`, `1/2]`). Confirmations' Kind row names the category (`GPUNode`, `DedicatedAICluster`) rather than a mix of `node` and `DAC`. The edit-tenant form says what `^o` does — opens the tenancy's page in the DevOps portal — on its own line.
- **TUI polish from the UX review.** The command palette lists the items you ran this session first (under **recent**), names each group once, shows only short aliases, and marks the open category. Row picker badges are left-aligned, and a filterable picker says typing filters. The edit-tenant form shows `required`/`optional` placeholders, marks a missing name in place instead of a toast, and `Enter` moves to the next field (saving on the last; `Ctrl+S` saves from any field) rather than saving from wherever you are. An irreversible confirmation's hint says a lowercase `y` cancels. The loading screen shows `q quit`. A failed load in a category that can refresh says `r retry`. The list panel is titled with its row count (`3 rows`) and the detail breadcrumb no longer repeats the row, since the breadcrumb and the panel title said the same thing.
- **TUI log view in the frame, with filters.** The `` ` `` log now has the env bar, a breadcrumb (`following`/`PAUSED`, active filters, `[shown/total]`), a bordered panel and a key footer, like every other screen. `/` filters entries by text as you type, `l` cycles the minimum level (all → info → warn → error), and `Esc` clears the filters before it closes the log. A filter that hides everything says so.
- **TUI detail view shows fields, not just JSON.** Readable labels (`totalReplicas` → Total replicas, `tenantId` → Tenant ID), plain values first, nested objects as indented sections, lists of objects as numbered entries, long values wrapped. `Tab` switches to the raw JSON and back. The breadcrumb shows the layout and scroll position (`[JSON · 40%]`) instead of the list's stats. The preview pane uses the same layout with one level of nesting expanded, so `owner {…}` now shows the owner's fields; both are built from the item's JSON, so they show exactly what `o` copies.
- **TUI export dialog redone as a save dialog.** It shows the folder the file goes to (`~/…`, shortened from the left when long) and an editable name (`Tab`), lists folders without permissions or sizes, and fits its contents. `Enter` exports into the folder shown — before, it exported into the *highlighted* subfolder, so the current folder (or an empty one) couldn't be chosen. `→`/`l` open a folder, `←`/`h` go up. A notification now confirms where the file was written; before, a successful export closed silently.
- **TUI columns fit their contents.** Each column is as wide as its header or its widest value, and the rest of the width is shared as before. On a narrow terminal long values (names, OCIDs) shorten first while short ones (`true`, `90d`, counts) and Status stay whole; when even that doesn't fit, columns drop from the right — never the first or Status — and the panel title says `· 2 columns hidden`. Headers no longer read `Interna…`/`Heal…` at 120 columns or `T… F… H…` at 80. Only the sort column carries an arrow (the `↕` markers are gone: `?` lists the sorts, and `s` underlines their letters). Empty cells show a muted `—`.
- **One key notation across the TUI.** Help, the footer, the palette and every modal write keys the same way: `C` for Shift+C, `^x` for Ctrl+X, `/`, `:` (help used to say `<shift+c>`, `<ctrl+x>`, `</term>`, `<:cmd>`). Help gathers every sort into one **Sort** section by column, and its labels are sentence case. The export dialog's hint matches the other modals. The footer keeps `/ filter` and `: command palette` and drops category actions first when it runs out of room.
- **TUI safety and feedback.** Production is a red `PROD` badge in the env bar and a `PRODUCTION` badge on every confirmation's context line; dev and preprod look as before. Confirmations for cordon, uncordon, drain, node restart and scale-up now say what they do (scale-up names the pool's current and target size, or that it is already there). Error toasts no longer fade after 8 seconds: they wrap to three lines and stay until `Esc` in the list or details view, which then dismisses them instead of backing out. An empty table says why — loading, the filter or faulty-only mode hiding every row (with how to undo it), or no rows in this context.
- **TUI command palette on `:`.** It fuzzy-searches categories (by name or any alias), environments (recent slots first, in environment-scoped categories), the selected row's actions and sorts, Export CSV, and the alias, faulty and preview toggles. An exact alias still wins on `Enter`, so `:dac` + `Enter` opens DedicatedAICluster as before. Actions run exactly as their key would, confirmations included. It replaces the status-bar alias input.
- **TUI preview pane (`v`).** On terminals at least 160 columns wide, it shows the selected row's fields beside the table and follows the cursor. Nested objects collapse to `{…}` and lists to `[n]`. It stays on for the session and is hidden while the terminal is too narrow.
- **One-time "Keys changed" note.** After an upgrade that moves keys, a note in the corner says what changed. Any key dismisses it and still does its usual job. The keymap version you've seen is saved in `~/.config/toolkit/ui.yaml`.
- **Delete orphaned InferenceServices**: `Ctrl+X` on an InferenceService row, `toolkit delete inference-service <name>` (aliases `isvc`, `inferenceservice`), and the MCP `delete_inference_service` tool. Only an orphan is deleted: a dedicated endpoint none of whose DAC names exists in any DAC API (`ome.io`, `ome.oracle.com`, and `gpu-alfred.generative-ai.oracle.com`, which the toolkit doesn't list). Both the endpoint's DAC reference and its DAC-named namespace are checked. Shared endpoints and endpoints whose DAC exists are refused, since the control plane owns their lifecycle, and a DAC lookup that fails for any reason other than "not there" also refuses. An endpoint not yet being deleted gets a normal delete. One whose deletion has been pending for over 10 minutes is force-deleted: its `inferenceservice.finalizers` finalizer is removed with a JSON patch guarded by `resourceVersion`, and a finalizer the toolkit doesn't know is never removed. The two steps are separate calls so the controller gets its chance to clean up first. Every surface checks the target before acting: the CLI's `--dry-run` and the TUI modal name the real action (`delete` or `force-delete`), and a refusal comes before any prompt. On dp-prod-ord, both orphaned endpoints have been stuck deleting since 2026-04-02 and 2026-06-25, holding their namespaces in `Terminating`; the controller can't finalize them because the endpoint's model or DAC is gone.
- **The TUI's faulty toggle (`Ctrl+Z`) also lists rows naming a parent that doesn't exist**: the rows `toolkit doctor --relations` reports as FAIL, such as an endpoint whose DAC was deleted or a node in a pool absent from terraform. Tenancies missing from the metadata (doctor's WARN) don't count, since they are a metadata gap rather than broken state and would flag about 3 in 10 imported models on dp-prod-ord. The TUI loads categories on demand, so a reference is checked only once its parent category is loaded. A node whose pool is missing is flagged even when some GPU pool sources failed to load: the pool may only be unloaded, but a broken source needs attention too. On dp-prod-ord this adds one InferenceService: an endpoint whose DAC is gone and that has no pods, but still reports `Ready`. The other orphaned endpoint was already faulty because it isn't ready.
- **`toolkit doctor --relations`** checks the data's cross-category references. It loads every category for the environment, concurrently, and checks every relation in the registry, the same ones the TUI drills through. Each relation gets one row: PASS, or FAIL when rows name a parent that doesn't exist, such as an endpoint whose DAC was deleted, a pod naming a missing runtime, or a node in a pool absent from terraform. A final tenancy check WARNs for tenant-owned rows whose tenancy resolves to no known tenant, which is a metadata gap rather than broken state. Table output names the first few dangling rows. `-o json`/`yaml` lists every one under a new `items` field. A FAIL makes doctor exit non-zero; a WARN doesn't. Two relations only check the rows they apply to: dedicated endpoints for a DAC, and pods in DAC-named namespaces. Endpoints that leave their runtime to deploy-time selection appear as a note. If some GPU-pool sources fail to load, a missing pool stays FAIL, with a note naming the failed sources. Without the flag, doctor stays a local, network-free check as before. On dp-prod-ord it runs in about 5s and reports the 2 endpoints whose DAC is gone, the 1 whose imported model is gone, and 141 rows across 65 unresolved tenancies.
- **`o` jumps from a row to what it relates to, replacing the parent jump.** On any scoped category, `o` lists the rows the selected one relates to, through every relation into its category. For example, an InferenceService lists its tenant, model, DAC and runtime, and a GPUWorkload its tenant, node, DAC and runtime. Choosing one jumps there and lands on that row. The picker starts on the row's parent (the scope drilled in from, else the structural parent such as a workload's node or an endpoint's DAC), so going up is still `o`, `Enter`. With a single target, `o` jumps directly, and with none it shows a toast. It is not on `g`, which the table keeps as go-to-top. Targets are left out when the row is known not to exist: the BaseModel and ImportedModel keys split endpoints by model name (imported model names are OCID resource ids, `amaaaaaa…`), so an endpoint offers exactly one model category, and a target in a loaded category with no row of that name is dropped. Targets in categories not yet loaded are kept, because the jump loads them. The parent names come from the same join keys as the drill-in, run in reverse (`relations.Grouped.ParentName`).
- **MCP `list_related` tool**: lists the rows of `category` related to one parent row, given by `parent_category` and `parent_name`. It uses the same relations and join keys as the TUI drill-in and `toolkit get --related-to`, and returns the same item objects as the category's `list_*` tool. Examples: a DAC's pods (`gpuworkload` ← `dac`), the endpoints serving a model, or what uses a runtime. The tool description lists every relation, so an agent can see the valid pairs. An unrelated pair is an error that names the valid `parent_category` values. An empty result carries a warning, because `parent_name` must match exactly. `filter` and `limit` work as on the `list_*` tools.
- **`toolkit get --related-to <category>/<name>`** keeps only the rows related to one parent row, using the same relations as the TUI's drill-in. Examples: `toolkit get gpuworkload --related-to dac/<name>` lists a DAC's pods across every node, and `toolkit get inferenceservice --related-to servingruntime/<runtime>` lists every endpoint naming the runtime. Category aliases work (`dac/`, `t/`, `sr/`, …). The name is matched exactly, case-sensitively, against the parent row's first column, the same as in the TUI, so tenants that differ only by case stay distinct. The flag combines with `--filter`. A parent category that isn't related is rejected with the valid parents listed, e.g. `GPUPool is not related to GPUWorkload; use one of: tenant/, gpunode/, dedicatedaicluster/, servingruntime/`. An empty result prints a warning on stderr, so a mistyped name isn't mistaken for "nothing related". Shell completion offers the valid `<category>/` prefixes. Without the flag, output is unchanged.
- **Drill from a tenant or a runtime to the pods and endpoints using it.** With a tenant scope active, `:gw` and `:is` list the tenant's GPU pods and endpoints, matched by their resolved owner. `Enter` on a tenant still opens its limit overrides, and rows whose tenancy doesn't resolve are under no tenant. `Enter` on a ServingRuntime lists the endpoints naming it in `spec.runtime`. With that scope active, `:gw` lists the pods running it by their `serving-runtime` label, which also covers endpoints whose runtime OME selects at deploy time. Legacy endpoints never match a runtime: their runtime is a legacy `ome.oracle.com` one that can share an `ome.io` runtime's name (`gais-contentmoderate` does on dp-prod-ord).
- **Drill from a DAC to its pods, and from a model to its endpoints.** With a DAC scope active (`Enter` on a DAC), switching to GPUWorkload (`:gw`) lists the GPU pods in that DAC's namespace across every node. `Enter` on a BaseModel or an ImportedModel now lists the InferenceServices serving it (`y` still opens details). A BaseModel only counts endpoints using the shared-catalog model, so tenant-imported endpoints never match it. An ImportedModel matches by model name, which also covers the endpoint that references a tenant-labelled ClusterBaseModel (its `importedModel` flag is false). Legacy endpoints match neither, since their model is a legacy `Model` CR. Without a breadcrumb, `o` still goes from a workload to its node, from an endpoint to its DAC, and from an imported model to its tenant. These links are *references* (the child names the parent in a field), not structural parents.
- **New `InferenceService` category** (alias `is`), surfacing OME `InferenceService` CRs (`ome.io/v1beta1`) in the TUI, `toolkit get is`, and the MCP `list_inference_services` tool. Columns: Name, Namespace, Tenant, Model, Runtime, Replicas, Ready, Age. There is no Type column, since a dedicated row is recognizable by its tenant and DAC-ID namespace; `type` stays in `-o json` and the MCP output, and filtering still matches it. It extends the tenant hierarchy to Tenant → DedicatedAICluster → InferenceService: rows are grouped by namespace, which for a dedicated endpoint is the DAC ID, so **`Enter` on a DAC now drills into its inference services** instead of opening details (`y` still opens details, as on GPUPool/GPUNode). Shared endpoints have type `on-demand`; their namespace is the model name and they have no tenant, so they appear only in the unscoped list. A row is dedicated when it carries the `ome.io/dedicated-ai-cluster` annotation or lives in a DAC-named namespace. `-o json` carries an `importedModel` flag for tenant-imported models. A row whose `Ready` condition isn't `True` is faulty. The category is live-watched and supports `o` (parent), `s t`/`s a` sorts, copy-tenant, and the metrics shortcut: dedicated rows use the DAC filter and on-demand rows the base model's display name, the same plan GPUWorkload uses. `deploymentMode` is not shown because it is `RawDeployment` on every endpoint.
- **Legacy `ome.oracle.com/v1alpha1` InferenceServices are now listed** alongside the `ome.io/v1beta1` ones, in the TUI, `toolkit get is`, and MCP `list_inference_services`. Endpoints on legacy DACs were invisible before, so `Enter` on a legacy DAC always drilled into an empty list. On dp-prod-ord that was all 9 legacy DACs' endpoints. The legacy spec keeps its serving config under `spec.predictor`: replicas come from `predictor.{min,max}Replicas`, the runtime from `predictor.model.runtime`, and the model from the first `predictor.model.modelRefs` entry (a legacy `Model` CR), falling back to `predictor.model.name`. A row is dedicated when it has a `dedicatedAIClusterRef` or lives in a DAC-named namespace. Legacy rows carry `legacy: true` in `-o json` and MCP output, `/legacy` filters to them, and the category watch also covers the legacy API. A cluster without the legacy CRD lists the `ome.io` endpoints as before, but any other legacy list failure is an error rather than a silently short list. Legacy endpoints can be restarted too (see below).
- **Rolling restart for InferenceServices**: `shift+r` on an InferenceService row, `toolkit restart inference-service <name>` (aliases `isvc`, `inferenceservice`), and the MCP `restart_inference_service` tool. All three stamp the CR's `restartedAt` annotation with the current UTC time (RFC3339) using a JSON merge patch, which is the scripted form of the `kubectl annotate inferenceservice … restartedAt=… --overwrite` runbook step. The OME controller then rolls the serving pods. The call is fire-and-forget, a recoverable y/N confirm like a node restart. The TUI modal shows the row's current `Ready` state, and the result appears as a toast. In the CLI and MCP, the namespace is optional: without it the name is searched across all namespaces and must be unique, and an ambiguous name errors with the candidate namespaces. The CLI resolves the namespace before prompting, so `--dry-run` proves the target exists and the prompt and audit log carry `<namespace>/<name>`. `--namespace` has no `-n` shorthand because every mutation command already uses `-n` for `--dry-run`. Legacy `ome.oracle.com/v1alpha1` endpoints get the same patch on the legacy API: the patch goes to `ome.io` first and falls back to the legacy API when the endpoint isn't there, and name resolution searches both. The legacy controller copies `restartedAt` onto the pods the same way. On dp-dev-ord and dp-ppe-ord, every past change to `restartedAt` alone produced a new ReplicaSet, and legacy deployments roll with `maxSurge: 2, maxUnavailable: 0`.
- **New `ServingRuntime` category** (alias `sr`), surfacing OME `ClusterServingRuntime` CRs in the TUI, `toolkit get servingruntime`, and the MCP `list_serving_runtimes` tool. Columns: Name, Hardware, Image, Size Range, CPU/Mem, GPUs, Auto-Select, Disabled.

  Three columns are collapsed for the table and kept whole in `-o json`. **Hardware** reduces accelerator classes to GPU families with a raw count (`ac: a100-80gb, h100, a10 (19)`), falling back to node-affinity instance types (`it: BM.GPU.H100.8, …`) when no accelerator classes are set; the `ac:`/`it:` marker matters because the two constrain scheduling differently. **Image** drops the registry host and org, which are near-constant across a fleet. **CPU/Mem** pairs the two quantities that are read together, leaving GPUs its own numeric column.

  Resources come from the ome-container's `limits`, falling back to `requests` with a `req:` marker when a runtime caps only the GPU — a scheduling floor and a cap are different promises, so the marker keeps them distinguishable, and the model stores the two in separate fields so `-o json` never labels one as the other. For a **multi-node** runtime (`engineConfig.leader` + `engineConfig.worker` rather than `runner`), the figures are the *total* across leader + worker×`size`, since the useful number is what it costs to serve the model rather than what one pod of it costs; `nodeCount` reports how many pods that is.

  Image, resources, and affinity are read from `spec.engineConfig` in preference to their top-level `spec` duplicates, with a debug log when the two disagree. That preference is load-bearing rather than cosmetic: on the indexed clusters four runtimes genuinely differ, and for one of them the running pods match `engineConfig`'s GPU count, not the top-level one.

  `autoSelect` is true when *any* `supportedModelFormats` entry sets it. A `disabled` runtime reports as faulty, so the faulty-only filter surfaces it. Namespaced `ServingRuntime` CRs are not included — like `BaseModel`, this is the fleet-level catalog. Filtering matches the raw values, so searching `h100-8` finds a row whose cell only shows `h100`.

  The **TUI** shows a slimmer five-column view built for placement and rollout scanning — Name, Hardware, GPUs, Image, Status — while `toolkit get` keeps all eight columns and their `--columns` keys. Its Hardware cell is GPU families only, with OCI shapes mapped to the same names (`BM.GPU.H100.8`/`BM.GPU.H100-NC.8` → `h100`, `BM.GPU4.8`/`BM.GPU.B4.8` → `a100-40gb`; unknown shapes pass through), so the cell reads the same whichever constraint is in force. GPUs shows a multi-node runtime as per-node × nodes (`8×2`), and sorts by the product. Status replaces the Auto-Select and Disabled flags with one word — `live`, `off` (auto-select is off) or `disabled` (wins over either) — and the filter matches it, so `/off` lists the runtimes the scheduler won't pick on its own. Size range and cpu/memory remain in the detail view.
- **`s g` sorts by GPU count** on ServingRuntime, GPUPool and GPUWorkload. The sort is numeric: these values order `1, 16, 2, 32, 4, 8` under a string compare, and blank cells sort as zero. ServingRuntime, GPUPool and GPUWorkload all title the column `GPUs`, so one binding covers all three.
- **`--env-region` accepts 3-letter region codes and `--env-type` accepts `ppe`.** `toolkit -m oc1 -r phx -t ppe` is now equivalent to `--env-realm oc1 --env-region us-phoenix-1 --env-type preprod`. Input is case-folded, so `PHX` works too. Resolution happens once, immediately after config load, on every entry point that feeds it — CLI flags, `~/.config/toolkit/config.yaml`, `TOOLKIT_*` env vars, and MCP per-call `env_region` / `env_type` overrides — so everything downstream sees only the canonical form. That matters because the region string reaches the OCI SDK and OCID construction verbatim: an unexpanded code would silently produce a wrong endpoint and wrong OCIDs rather than failing. A short code that isn't a known region is a hard error naming the flag (`unknown region code "zzz"`), not a pass-through, since the loader's `environment is not valid or in the list` reads as though the realm or type were at fault. The MCP path is the one exception — `envFor` has no error return, so an unresolvable code there is logged and passed through to be rejected downstream, which fails closed. Values that already contain a dash are treated as full identifiers and left alone, so existing configs and scripts are unaffected. When an alias is expanded, one line at startup records what it resolved to.
- **Single-letter shorthands for the three env-targeting global flags**: `-t` (`--env-type`), `-r` (`--env-region`), `-m` (`--env-realm`). They are persistent, so they work on every subcommand — `toolkit -m oc1 -r us-ashburn-1 get tenant -o tsv`. Realm takes `-m` (real**m**) rather than `-R` deliberately: no two flags that decide the blast radius of `drain`/`terminate` should differ only by a shift key. The long forms and the `env-type` / `env-region` / `env-realm` config keys are unchanged.

### Changed
- **BREAKING (TUI keys): sorting moves to `s` + the column's letter.** `s n` sorts by Name, `s t` by Tenant, `s s` by Status, `s g` by GPUs, and so on. A column's letter is its first letter, unique within the category. While `s` is pending, the header underlines each column's letter. The `Shift`+letter sort keys are gone, so every `Shift`+letter is now one row action in every category: `Shift+R` Restart, `Shift+C` Cordon, `Shift+D` Drain, `Shift+U` Scale Up, `Shift+E` Edit Tenant. `G` now goes to the last row; it was Sort GPUs.
- **TUI redesign.**
  - The six-line header, help grid and logo give way to an env bar (realm › type › region · context · k8s, LIVE, version), a breadcrumb (category path, filter, sort, faulty and history chips, row stats) and a footer of the keys that matter here. The table gains about five rows.
  - The table and details sit in a rounded panel titled with the category and row count. The selected row is filled with the accent color, and Status cells are colored by meaning (red failed or deleting, amber transitional, green healthy).
  - Modals draw over the dimmed view in a shared titled box. Confirmations show what, where and why, with Cancel/action buttons; `Enter` never confirms an irreversible action, which still needs a capital `Y`. The row picker gets category badges, scrolling and type-to-filter. Notifications stack in the bottom-right corner.
  - **Help no longer gets cut off.** Its sections flow into columns, and when they still don't fit it scrolls with a position indicator.
  - Colors come from one palette of named roles, with light and dark variants chosen from the terminal's background.
- **The TUI now runs on the Charm v2 stack** (bubbletea, bubbles, lipgloss, glamour v2).
- **BREAKING: "reboot" is now "restart" everywhere.** The CLI command `toolkit reboot <node>` is now `toolkit restart node <node>`, next to `toolkit restart inference-service`. The MCP tool `reboot_node` is now `restart_node`, so update MCP permission allowlists that name it. The audit-log action is now `restart`. In the TUI, `Shift+R` is a single **Restart** key that soft-resets a GPU node's instance or rolling-restarts an InferenceService, and the node's transient status reads `Restarting`. The old names are removed rather than kept as aliases. The operation itself is unchanged: an OCI soft reset.
- **Long-ID columns truncate in the middle.** The Model column of InferenceService, DAC and GPUWorkload holds imported models' OCID resource ids. These share a long prefix (`amaaaaaa7mjirbaa…`), so cutting the end kept only the shared part. Those columns, and the other columns where cutting the end merged distinct values on dp-prod-ord, now keep both ends: Runtime (InferenceService, GPUWorkload), the TUI's ServingRuntime Name, Tenant OCIDs, and the tenancy-override Value. The selection came from measuring every TUI column on live rows. PropertyRegionalOverride Value is unchanged, because middle truncation collides more there.
- **The InferenceService Model column no longer appends `*` to imported models.** It was cut off in the narrow column anyway, and imported models' names are OCIDs, which say it already. The `importedModel` flag is now set by name, so it also covers the endpoint that references a tenant-labelled ClusterBaseModel. That endpoint previously reported `false`.
- **ImportedModel shows one row per model.** A tenant's model lives in `default` and is copied into a DAC's namespace for serving (21 models on dp-prod-ord, 46 rows). Each copy used to be its own row with the same tenant and name, so details, copy, edit-tenant and metrics on one copy could act on another. The copies (identical specs) are now one row. `namespace` is the primary copy (`default` when present), the new `copies` field lists the others, and the TUI's Namespace column shows them all. `m` (metrics) on an imported model opens the dashboard of the DAC holding its copy. When several DACs serve the model, as for two models on dp-prod-ord with copies in three DACs each, a picker lists them and you choose one. Before the merge, metrics only worked from the DAC copy's own row.
- **Drain logs every step, without flooding the log.** Each milestone is logged: cordon, the restart plan (or that nothing needed restarting), what the wait and evict phases still wait on with their deadline, each eviction, and done or failed. Lines that repeat (what a phase still waits on, a PodDisruptionBudget refusing an eviction) are logged when their content changes and otherwise at most once a minute, instead of every 10s poll, so a long PDB block no longer pushes the start of the drain out of the TUI's 1,000-line log window. kubectl's drain warnings (e.g. ignored DaemonSet pods) are logged once. Pods whose emptyDir data eviction loses are now warned about explicitly, because kubectl's own warning for that is overwritten by its later filters for any controller-managed pod. `toolkit drain` also prints these milestones on stderr, since its log goes to a file and the command can block for tens of minutes.
- **`drain` is now safe and resumable** (CLI `toolkit drain`, TUI `shift+d`, MCP `drain_node`). It follows the production GPU drain runbook: cordon; refuse a node running active fine-tuning (`finetunedmodel-name`), `ome.io/trainingjob`, or `replicationJob` pods; rolling-restart every InferenceService on the node with `minReplicas <= 1` (`spec.engine` for `ome.io`, `spec.predictor` for `ome.oracle.com`; unset counts as 1), whose surge rollout moves it to another node before its old pod stops; wait up to 20m for those pods to leave; then evict the rest kubectl-style (DaemonSets ignored, emptyDir data deleted, up to 10m). A failure before eviction uncordons a node the drain cordoned; a failure during eviction leaves it cordoned. Previously drain evicted without cordoning, so evicted pods could land straight back on the node, and the TUI cut drains off after 30s.

  The drain is a state machine recorded in the Node's `toolkit/drain` annotation and advanced by `resourceVersion`-guarded patches, so it outlives the process that started it and concurrent drivers never repeat a step. The CLI still blocks, and re-running it resumes an interrupted drain. The MCP `drain_node` returns at once with the drain's status, the server drives the drain in the background, and the new read-only `get_drain_status` tool reports its phase, deadline, and what it still waits on.
- **`toolkit get` and the MCP list tools now resolve tenant names** for DedicatedAICluster, ImportedModel, GPUWorkload and InferenceService, matching the TUI. Before, those surfaces never loaded tenants, so DAC and ImportedModel output was keyed by the raw `tenancy-id` suffix and no row carried an owner. Each resolved row now gains an `owner` object (`name`, `ids`, `is_internal`, `note`) in `-o json` and MCP output. The table's Tenant column shows the tenant name for DAC and ImportedModel, and `--filter` / MCP `filter` match it. The raw `tenantId` field is unchanged, and rows whose tenancy isn't in the tenant list keep the raw key and have no `owner`. Resolution reads the tenancy overrides from `--repo-path`, which every `get` already requires. If that load fails, the rows still print unresolved, with a warning on stderr or in the MCP `warnings` field.
- **The MCP server no longer emits `notifications/message` frames.** MCP's logging feature is deprecated as of protocol version 2026-07-28 ([SEP-2577](https://modelcontextprotocol.io/seps/2577-deprecate-roots-sampling-and-logging)), and every message the server sent on that channel was already delivered in-band by the tool response: loader warnings and incomplete GPU-pool enrichment via the `warnings` envelope field, handler failures and `confirm=true` refusals as a tool error (`isError` plus the cause), and mutation success as the `mutationResult` payload (`status`/`action`/`kind`/`target`). Clients reading the response — the documented contract — see no change. Clients that only listened for `notifications/message` should read the response instead. The two GPU-pool warnings now also write to `cfg.LogFile`, matching what mutations already did.

### Fixed
- **`Esc` in the filter or command input no longer drops the drill-in.** It closes the input and clears an applied filter, as before, but leaving a scope now takes a second `Esc`.
- **A backtick typed into the filter or command input is text.** It used to open the log view.
- **Switching environments no longer carries state over from the previous one.**
  - **Scope:** a scope picked in the old environment, through `o` or `Enter`, survived a switch from the Environment list. That switch lands on Tenant rather than switching in place, so for example a DAC picked before the switch still filtered `:gw` and `:is` afterwards. The scope is now cleared on every switch.
  - **In-flight results:** results that land after a switch are dropped, because pool names and node IPs repeat across environments. This covers repo reloads, which used to merge the old environment's tenants, overrides and GPU pools into the new one. It also covers cordon, restart, scale, terminate and DAC delete results, which used to mark or remove the new environment's same-named row, and InferenceService delete plans, which could open a confirm modal for the new environment's same-named endpoint.
  - **Captured environment:** actions now capture their environment and kubeconfig when started, instead of reading them when the background job runs.
- **GPU pool enrichment no longer writes the live pool list from a background job.** The job read the environment, kubeconfig and GPU nodes, and wrote pool fields, while the UI loop was also reading them, which was a data race. It now runs on a snapshot, and the result (ID, actual size, status) is merged back by pool name on the UI loop.
- **oc1 environments load again with a current genai-shepherd-flocks.** Since #3665 (2026-09-30), `shep_targets` reads the oc1 targets from a child module (`oc1_prod = module.oc1_inventory.oc1_prod`, source `../oc1_region_inventory`). The toolkit's HCL evaluator didn't follow module calls, so every oc1 tenancy was skipped with a warning, and loading any oc1 environment failed with `environment is not valid or in the list`. The TUI, `toolkit get`, `doctor` and MCP were all affected. The evaluator now follows local module calls (`./`, `../`), recursively up to 8 levels: a module's inputs are evaluated in the caller and layered over its variable defaults, and its outputs are exposed as `module.<name>.<output>`. A module's locals and outputs are resolved separately, because a module commonly exports a local under its own name. Remote module sources are skipped. The evaluator also gains `startswith`, `alltrue`, `split`, `concat`, `regex`, `try` and `can`, which the inventory module uses. On the current repo, 18 service tenancies load (15 before), and dp-prod-ord and dp-ppe-ord pass every doctor relation check except the known orphan endpoints.
- **GPU pools from the OKE nodepools module load again.** Since the module started reading a cloud-init script with terraform's `file("${path.module}/…")` (genai-shepherd-flocks #2993, 2026-08-25), the toolkit's HCL evaluator failed on its `base_config`, and with it every pool in the module. Every GPU pool load was partial in every environment, so `doctor --relations` could only WARN about nodes in missing pools, and the TUI never checked them. The evaluator now supports `file()` and `path.module`. On dp-ppe-ord, doctor now FAILs the 14 nodes of `gais_inference_h100_cn_02`, a pool added on 2026-10-13 that a stale repo checkout doesn't have.
- **Two DAC recipes in `docs/recipes.md` filtered on a `.tenant` field that DAC JSON doesn't have.** They used to silently produce zero counts. They now use `owner.name`, the resolved tenant.
- **LimitDefinition was missing the 312 splat throttle definitions.** The limits Terraform module appends `limits_definitions/splat_limit_definitions.json` (a bare array) to `oc1_limits_definition.json` as another group, but the toolkit only read the oc1 file. The splat throttles were missing from LimitDefinition in the TUI, `toolkit get` and MCP, and their regional overrides couldn't be reached by drilling in from a definition. `doctor --relations` found it, because two limit regional overrides named a definition that "didn't exist". The splat file is now loaded too: 162 + 312 = 474 definitions on the current repo. A repo revision without the file still loads. The model gains `operation_id`, `throttle_dimension` and `default_value`, and the operation ID is filterable.
- **Cluster rows loaded before the tenants stayed unresolved.** Tenants load only when a Tenant or override category is visited. After an environment switch while viewing, say, DACs, the DACs loaded first and were never re-resolved once the tenants arrived: they stayed keyed by raw tenancy-id, so drilling in from their tenant showed nothing. Loading tenants now re-resolves every loaded DAC, ImportedModel, GPUWorkload and InferenceService, the same step saving tenant metadata already ran.
- **MCP `restart_inference_service` audit-logged a bare name when the namespace was omitted.** The audit target was built before the namespace was resolved; it is now resolved first, as in the CLI, so the audit log and result carry `<namespace>/<name>`. A refused call (no `confirm`) still touches nothing.
- **Tenancy overrides vanished for tenants renamed by metadata.** When `metadata.yaml` gave a tenant a name different from its override directory, `Tenant.Name` took the metadata name but the three tenancy-override maps stayed keyed by the directory name. Drilling from that tenant into its overrides showed nothing. The override maps are now re-keyed by the resolved tenant name. Each override's `tenant` field still records its source directory. Override directories whose tenancy resolves to the same tenant name are merged into one Tenant, as are metadata-only entries that share a name with an existing tenant.
- **Ownership of a tenancy claimed by two tenants could change between runs.** Tenants were built by ranging over a Go map, and the tenancy-suffix lookup let the last claimant win. A DAC, imported model, workload or endpoint owned by an OCID filed under two directories could therefore resolve to either tenant. dp-prod-ord has 14 such OCIDs (e.g. `OABCS1`/`oabcs1`, `rbcpreprod`/`rbc_preprod`, `cldhorizonsqa` with and without a trailing space). Tenants are now sorted by name with sorted IDs, the first claimant wins, and every tenant that shares an OCID lists the others in a new `shared_with` field. Those tenants are marked faulty (so `Ctrl+Z` surfaces them), and their names are filterable.
- **ServingRuntime rows went stale or vanished across reloads.** `ServingRuntimes` was missing from both lists of lazily-loaded fields on `Dataset`. Because `MergeReloadedRepoData` didn't preserve it, every repo file change wiped the loaded runtimes and forced a reload. Because `ResetRealmScopedFields` didn't drop it, and the category only loads when the field is empty, switching environments kept showing the previous cluster's runtimes. A reflection-based drift test now requires every `Dataset` field to be classified as live or repo-owned, and checks that every live field is preserved by the merge and dropped by the reset.
- **GPUWorkload tenant names didn't update after saving tenant metadata.** `applyTenantSave` re-resolved owners only for the tenant-keyed DAC and ImportedModel maps. GPUWorkload rows kept showing the raw tenancy suffix and could hold `Owner` pointers into the old `Tenants` array. The node-keyed GPUWorkload map and the namespace-keyed InferenceService map are now re-resolved too.
- **`Tab` / `Shift+Tab` skipped `ServingRuntime`.** The cycle's upper bound was hard-coded to `DedicatedAICluster`, so the category added after it was unreachable by tabbing. The cycle now runs over every data category (everything except `Alias`) through a shared `domain.LastDataCategory` bound, and a drift test fails if a category falls outside it.
- **`toolkit get <category> --filter <no-match> -o json` emitted `null` instead of `[]`**, breaking `| jq '.[]'` on the ordinary "filter matched nothing" result. `output.WriteJSON` documented that it never emits a null document, but its guard only caught an untyped nil; a filter with no matches produces a *typed* nil slice (`[]T(nil)`), which is a non-nil `any`, so the guard never fired. Nil slices now render as `[]` and nil maps as `{}`. `-o yaml` had the same defect and is fixed the same way, so the two formats agree on how an empty result looks. Structs and nil pointers are unaffected — `toolkit config -o json` still emits an object, and `null` remains the encoding for a genuinely absent object.
- **TUI sorting on a percentage column mis-parsed padded cells.** `parsePercent` stripped the `%` before trimming whitespace, so any value with a trailing space (`"37% "`) failed to parse and sorted as 0. Whitespace is now trimmed on both sides of the suffix strip.
- **MCP notification assertions broke under `go-sdk` 1.7.0.** The bump negotiates protocol 2026-07-28, which makes the logging level per-request via `_meta` (SEP-2575) instead of session-wide via `logging/setLevel`. The server re-derives the level from every request, so a request without one silently suppressed all frames and 19 tests timed out. Superseded by the removal above.

### Internal
- The join keys behind the relations moved from the TUI into a new `internal/relations` package, so the TUI drill-in and `toolkit get --related-to` filter through the same definitions. `relations.Grouped[T].Filter` and `relations.Flat[T].Keep` apply a parent scope. `TestKeysMatchRelations` requires a key set for every scoped category, matching the domain registry, and `domain.Category.ScopedBy()` lists a category's parents across both relation kinds.

## [0.3.0] - 2026-05-19

### Breaking
- `GpuPool` JSON shape changed: fields now use lowercase / camelCase tags (`name`, `shape`, `actualSize`, `capacityType`, `isOkeManaged`, `availabilityDomain`) to match every other model in `pkg/models/`. Scripts that targeted `.Name` / `.Shape` etc. on `toolkit get gpupool -o json` or the MCP `list_gpu_pools` output need to switch to the lowercase keys.

### Added
- `toolkit doctor` — read-only health-check subcommand that aggregates the file-existence and schema checks scattered across the subcommands into one report. Each row is PASS / FAIL / SKIP with a remediation hint; exit non-zero on any FAIL. Renders `table` (default), `json`, or `yaml`.
- `docs/recipes.md` — four end-to-end flows: wire `toolkit mcp` into Claude Desktop / Claude Code / Codex CLI; GPU node maintenance window (cordon → drain → reboot → uncordon); tenants → CSV / TSV → spreadsheet; daily GPU-pool digest to Slack via `jq` + `curl` (cron / launchd).
- Architecture mermaid diagram in the README showing how config + data sources funnel through the loader into the four surfaces (TUI, headless `get`, MCP, mutations).

### Changed
- Every Kubernetes client call now has a 30s per-request timeout (`internal/infra/k8s/client.go`). A broken or unreachable cluster fails the spinner in seconds instead of hanging on TCP dial / TLS handshake. Override via `k8s.RequestTimeout` before any client is built; setting it to zero restores client-go's no-timeout default.
- `release-drafter` autolabels PRs from conventional-commit prefixes (`feat:` / `fix:` / `refactor:` / `docs:` / etc.) and resolves the next version automatically (minor on `feat`, patch on most others, major on `breaking` label). Bumps the action to v6.
- CI now exercises `.goreleaser.yaml` on every push/PR via a `release-snapshot` job, so config drift fails fast instead of on tag push.
- `toolkit config --validate` is now schema-stable: pass and fail paths emit the same `{valid, config_file, error?}` shape; the redundant `config` key inside the `settings` map is dropped (the top-level `config_file` is authoritative); `--pretty` is exposed for parity with `toolkit get`.
- `cordon` / `uncordon` `--help` now carries a `Long:` block with examples to match the other mutation subcommands.

### Fixed
- README mutation table referenced flags that didn't exist (`--confirm`; `--size` on `scale gpupool`). The actual flag is `--yes` / `-y`, and `scale gpupool` derives size from Terraform.
- `docs/recipes.md` (introduced in this release) initially pointed `jq` at fictional fields (`.status` on GPU nodes; lowercase pool fields before the JSON-tag change; a `{status: .result}` shape in the audit log). Now matches the real envelope.
- `.goreleaser.yaml` cleared all v2 deprecation warnings: `snapshot.name_template` → `version_template`; legacy `brews:` block removed in favor of `homebrew_casks:`; `homebrew_casks.binary` dropped (auto-detected).
- `.github/workflows/release.yml` installs `syft` (was missing, killed the first v0.2.0 release attempt) and tracks Go version via `go-version-file: go.mod` instead of a hard pin.

## [0.2.0] - 2026-05-18

This release adds a headless CLI surface, an MCP server, and node/pool mutation subcommands. Everything previously available only through the TUI is now scriptable.

### Added

#### Headless CLI
- `toolkit get <category>` prints any category to stdout in `table | json | jsonl | yaml | csv | tsv` (`-o`, `--no-headers`, `--pretty`). Accepts the same aliases the TUI uses (`t`, `bm`, `dac`, `gn`, …); `toolkit get alias` lists them all.
- `toolkit config` prints the effective merged settings (defaults + `TOOLKIT_*` env + config file + flags) plus the resolved config-file path and an `exists` boolean. `--validate` mode runs `config.Validate()` and exits non-zero on failure, with a structured `{valid, config_file, error?}` payload on stdout.
- Mutation subcommands (`--confirm` required, `--dry-run` available, JSON audit log):
  `toolkit cordon` / `uncordon` (Kubernetes node), `toolkit drain`, `toolkit reboot`, `toolkit scale gpupool`, `toolkit delete dac`, `toolkit terminate` (OCI instance).
- `toolkit completion` for bash/zsh/fish/powershell.

#### MCP server
- `toolkit mcp` exposes a stdio MCP server. Read tools cover every category: `list_tenants`, `list_base_models`, `list_gpu_pools`, `list_gpu_nodes`, `list_dacs`, `list_environments`, `list_service_tenancies`, `list_model_artifacts`, `list_definitions`, `list_tenancy_overrides`, `list_regional_overrides`, `list_aliases`.
- Mutation tools mirror the CLI subcommands and are gated on `confirm=true`; failures surface via `notifications/message` and a unified audit log.
- `mutation_env_override_allowed` flag opts mutation tools into per-call env override (default off — operator's startup env is the maximum blast radius).

#### TUI
- GPU node inspection reports pod-level issues (Pending/Failed pods scheduled to the node).
- Table stats: aggregate counts displayed in the status bar for GpuPool, GpuNode, and DedicatedAICluster.
- ScaleUp shortcut (`shift+u`) for OCI GPU instance pools (GpuPool view).
- DAC view shows model info plus Active vs Failed counts.
- GpuPool gains an `AvailabilityDomain` column (extracted from Terraform `placement_logical_ad`, supports string/list/`"all"`).

### Changed
- Terraform loader is partial-tolerant: `LoadGpuPools` returns a typed `PartialLoadError` instead of failing the whole load when one source can't be resolved. Both TUI and `toolkit get` surface the warning on stderr without dropping the rows that did load.
- TUI internals: typed messages route directly to typed handlers; per-generation cancellable load contexts replace the long-lived `m.ctx`; loader commands are pure; lazy loads carry generation guards; immutable lipgloss styles are centralized.
- `errors.As` replaced with a typed `errors.AsType` helper across the codebase.
- `GpuPool.InstancePoolId` → `GpuPool.ID`.

### Fixed
- `toolkit get` now reads `~/.config/toolkit/config.yaml` (previously the headless path ignored the user's config file).
- Filter debounce and stale-data guards no longer flicker results during fast typing.
- OCI helpers no longer nil-deref on the non-prod path (`client.Host` instead of `Endpoint()`) and the URL parser tolerates missing schemes.
- TUI list view bottom border no longer shifts after exiting detail view.
- `BaseModel.GetDefaultDacShape` no longer panics on unknown shapes.
- `UNKNOWN` region fallback replaced with a city-segment slug so special-region IDs resolve correctly.

### Build / CI
- Go toolchain pinned to 1.26.1 (closes stdlib CVEs).
- User manual added (`docs/`).
- SBOM + GPG-signed checksums produced by GoReleaser; Homebrew tap auto-updated.
